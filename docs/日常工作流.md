# 日常工作流

以下是普通业务入口。各组可用 `--help` 查看精确参数。命令前缀使用 `python -B -m resume_workflow`，也可使用 README 中虚拟环境的 `$py`。输入的 Markdown 与 JSON 使用 UTF-8。

| 目的 | 命令与事实边界 |
| --- | --- |
| 打开当前系统 | `workspace open` 查当前主资料、岗位、任务、参照和已存在的作品。 |
| 接收或更新资料 | `material init 背景 --file <文件>`、`material read 背景`、`material search <原句或词>`。直接编辑当前主文件，或用 `material update 背景 --file <新文件> --base-revision <先前读取的版本>`。保留冲突和修订来源。|
| 接收岗位 | `job import --id <ID> --jd <原始JD.md> --metadata <岗位.json>`，`job list/open` 查询。全文岗位的最小元数据是 `{"jd_status":"全文"}`。缺失 JD 或是否在招，分别保留真实缺口。 |
| 筛选并短列 | `screen create <筛选ID> --jobs <岗位ID数组.json>`；`screen brief <筛选ID> --materials 背景 兴趣 偏好`；`screen record <筛选ID> --spec <判断.json>` 保存人或模型读原文后的判断；`screen select <筛选ID> --jobs <选择数组.json> --mode parallel`。参考演练生成的 `inputs/screen.json`。 |
| 保存简历 | `task create <任务ID> --job <岗位ID> --author <作者>`，`task inputs <任务ID>`，`task save <任务ID> --spec <稿件.json> --author <作者>`。演练生成的 `inputs/draft.json` 展示来源、教育、模板参数与资源结构。正式稿使用你有权使用的真实资源。 |
| 接续已有稿 | `task open/versions <任务ID>` 定位旧稿，`task export-spec <任务ID> --revision <明确版本>` 查看依据与资源，`task continue <任务ID> --revision <明确版本> --author <作者>` 保留原依据另开版本。使用 `task inputs ... --from-task ... --revision ...` 时默认只复用版式；需要旧稿和历史依据才加 `--reuse draft`。 |
| 预览与审查 | `render html <任务ID>` 检查真实整页，`render pdf <任务ID>` 生成中间 PDF。用实际独立审件与绑定的作品走 `review record`、`render pdf --formal` 与 `deliver`。按[制稿与独审规则](../AGENTS.md)核事实、内容和整页；旧版通过不自动转签。 |
| 领取／进展／网申记录 | `record create <ID> --spec <事实.json>`，`record open/list` 查询。例子：`{"kind":"application","actor":"实际记录人","data":{"state":"prepared"}}` 仅表示准备。认定已投递须有真实日期和证据，不能从选择、交付或暂存推断。 |
| 保存点和恢复 | `checkpoint <独立位置>`，`--data-root <空恢复目录> restore <保存点>`，从恢复目录正常打开并保存。保存点覆盖已保存业务和所引原件，其余历史依赖明确基线；需要完整复制用 `backup`。根目录不得互相嵌套。正在使用的资料不要作为空恢复目录。 |

当前程序保留用户按需主动迁入的 `legacy` 与 `workspace merge`。先查各命令帮助和来源身份；确认使用者指定的原根、备份与冲突策略，再执行。默认示例从空资料起步，不要求历史系统、旧配置、既有照片、模型路由或旧聊天。

## 标准化岗位包导入（可选）

如果已有其他采集工具导出的本地岗位包，可以直接导入选中的岗位。包根下放 `jobs/*.md`；每份岗位文件的开头使用 YAML，至少含 `job_id`、`job_title`、`company`、`source_url`、`raw_description`、`source_visible_text`。原文描述必须能在采集时保存的可见文字中找到。导入读取本地包，不访问来源网址、不改包内原文件。已有真实岗位包应按实际采集范围记录来源和正文完整度。

下面在程序目录运行，使用包内两份虚构岗位，选择其中一份。沿用 README 的虚拟环境变量 `$py`。此演练使用单独的新资料目录。

```powershell
$batch = Join-Path $PWD.Path 'examples/standardized-intake'
$intakeRoot = Join-Path (Split-Path -Parent $PWD.Path) 'resume-intake-demo'
if (Test-Path -LiteralPath $intakeRoot) { throw '请另选一个新目录。' }
& $py -B -m resume_workflow --data-root $intakeRoot job ingest --source $batch --ids (Join-Path $batch 'selected.json') --id-prefix 'demo-' --actor 'synthetic-demo'
& $py -B -m resume_workflow --data-root $intakeRoot job open demo-fixture-data
```

`selected.json` 是原始岗位 ID 数组；省略 `--ids` 才会接入整批。结果中应新增一条 `demo-fixture-data`，并可通过 `job open` 查到来源和原文位置。对同一路径和未变输入再次执行导入，报告复用而不会新增重复记录。有冲突时，核对原输入与岗位身份再接续，不用改 ID 掩盖冲突。真实岗位要从个人明确指定的数据根进入；勿把示例导入正在使用的资料。
